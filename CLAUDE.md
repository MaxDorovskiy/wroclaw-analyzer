# Wrocław Analyzer — как работать с этим проектом

Младший брат киевского RE Analyzer (репозиторий flatfy-analyzer). Общего кода
нет — общие только решения, которые там окупились. Свой репозиторий:
https://github.com/MaxDorovskiy/wroclaw-analyzer (перенесён из папки
`wroclaw-analyzer/` flatfy-analyzer 18.09.2026 с историей). Подробности: `README.md`,
`docs/ARCHITECTURE.md`, `docs/API.md`, `DEFERRED.md`.

## Правила, которые дороже всего нарушать

0. **Сервер закрыт паролем** (`WRO_WEB_PASS`, логин `admin`; дополнительные
   логины `WRO_WEB_USERS="yulia:..."` с ролью «просмотр»). На Windows всё в
   `deploy/windows/env.ps1`, оттуда же читают триггеры и `safe_restart` —
   менять в одном месте. Пустой пароль = открыт всем (превью на копии).
   Действия каждого логина пишутся в `access_log` (раздел «Журнал»).
1. **Перед перезапуском — не идёт ли прогон.** Только
   `deploy/windows/safe_restart.ps1` (проверка условием, `-Wait` ждёт окна).
   Прогон продажи ≈ 1 час (выдача Otodom+OLX по 15 запросов/мин и хвост с
   карточками), аренды ≈ 30 мин; окна 11:00 / 17:00 / 02:30 Киев + 0-20 мин.
   Пауза — «Прогони → Пауза» или `POST /api/scrape/pause {"hours":N}`
   (0 = до отмены); сворачивает прогон за полминуты, статус `stopped`.
2. **Правки проверять на КОПИИ базы** (`WRO_DB=<копия>`, порт 8021).
3. **Анти-бан:** ≤15 запросов/мин на источник, источники по очереди, никогда
   параллельно с киевскими прогонами, если на том же IP. Otodom за DataDome:
   403 + `x-datadome` — это блок, а не сбой; лечится паузой, `fetch_mode=browser`
   (Chromium), дальше — прокси. Аренда уступает продаже (409 → повтор через 15 мин).
4. **На больших выборках не перебирать ORM-объекты** с `description_pl`/`raw_json`:
   `SCORE_COLUMNS`, `select(...)` нужных колонок, `bulk_update_mappings`.
5. **Ошибка записи в цикле прогона → `db.rollback()`**, иначе сессия отравлена.
   Отметка жизни — `scraper.beat_apart` (отдельная сессия), не commit на
   сессии с открытым курсором.
6. **Новая настройка не сохранится, пока ключ не в `SAFE_KEYS`** (config.py).
7. **Ручные правки владельца скрап не перетирает**: `condition_override`,
   `osiedle_override`, `note`, `is_favorite`, `dedup_detached` (`PROTECTED`).

## Источники — подтверждено на живых ответах 18.09.2026

Адаптеры писались без доступа к площадкам; первый запуск на ПК владельца их
сверил (подробно — `docs/RESEARCH.md` §2.3). Что важно помнить:

- **OLX режет Python-клиент по отпечатку** (CloudFront WAF, 403 «Request
  blocked» на любой адрес, даже robots.txt), а Chromium с того же ПК проходит.
  `fetcher` узнаёт такой блок, сразу зовёт браузер и до конца прогона ходит на
  этот хост только им (JSON — `fetch()` со страницы того же origin). Нужен
  Chromium: `playwright install chromium`. robots.txt OLX разрешает
  `/api/v1/offers/` и `/api/v1/friendly-links/`.
- OLX: настоящее число объявлений — `metadata.visible_total_count`
  (`total_elements` срезан на 1000); сдвиг страницы — из `links.next`; ~12
  рекламных на странице повторяются; friendly-links — путь через запятую;
  телефон API не отдаёт (только признак).
- **Otodom сворачивает квартиры застройщика в `relatedAds` записи-инвестиции**
  — без разворота (`flatten_items`) терялось 40% объявлений. Сами инвестиции
  (`estate=INVESTMENT`) и пригороды, помеченные городом (reverseGeocoding:
  county «wrocławski»), не берём; сколько не взято — в сообщении прогона.
- Otodom: этаж в выдаче — слово (`GROUND`, `THIRD`, `ABOVE_TENTH`); время в
  выдаче — польское местное даже с «Z» (карточка — честный UTC);
  `rentPrice.value=0` = «не заполнено». DataDome на httpx не сработал ни разу
  (≈1500 запросов за день при 14/мин).

Порядок при расхождении полей: `scripts/probe_sources.py` (sale и rent) →
сырые ответы в `%WRO_DATA%/probe` → правка `backend/app/sources/*.py` →
`scripts/make_fixtures.py` (обезличенные фикстуры из тех же ответов) →
`pytest tests -q` → `scripts/reparse.py` на КОПИИ базы, потом на боевой
(переразбирает `raw_json` без скрапа и снимает то, что адаптер больше не
берёт). OLX: id категорий/города меняются — при нуле объявлений проверять их
первыми (`olx_category_*`, `olx_city_id`).

## Перевод

Провайдер — настройка `translate_provider` (ollama по умолчанию — та же
карта, что считает ремонт в Киеве; anthropic / google / deepl по ключу).
Кэш по SHA-1 текста (`translations`). Подсказка и словарь терминов —
`translate.py`, меняли — поднять `PROMPT_VERSION`. Структурные значения —
словарём `i18n.py`; незнакомые копятся в `unknown_values` («Прогони»).
Оригинал хранится всегда. Карту делят несколько проектов, очередь ведёт
реестр заявок — см. «Общая видеокарта» ниже. Если сосед держит ТУ ЖЕ модель,
`translate_ollama_num_ctx` должен совпадать с его CONTEXT в `ollama ps` —
иначе модель перезагружается на каждый запрос (15–25 с против 0).

## Общая видеокарта — очередь ведёт реестр заявок

Блок ниже — из `C:\gpu-registry\clients\COMMON.md`, общий для всех проектов
владельца. Наш приоритет — **50, самый низкий** (решение владельца 26.09.2026):
переводы уступают всем, с re-analyzer (тоже 50) — по очереди. Реестр и его
файлы мы НЕ меняем; `backend/app/gpu_client.py` — байт в байт копия
`C:\gpu-registry\gpu_client.py`, править его тоже нельзя (обновлять — копированием
оттуда же).

Видеокарта (RTX 5070 Ti, 16 ГБ) с Ollama одна на все проекты владельца. Кто и когда её
занимает, решает **реестр заявок** на ПК с картой. Этот блок обязателен для проекта,
который обращается к Ollama.

- **Реестр:** `http://192.168.50.20:11435` — интерфейс для владельца `/`, правила `/api/gpu/rules`.
  С самого ПК можно `http://127.0.0.1:11435`.
- **Ollama:** `http://192.168.50.20:11434` (с ПК — `http://127.0.0.1:11434`).
- **Клиент:** `C:\gpu-registry\gpu_client.py` — один файл, только стандартная библиотека
  Python 3.8+. Скопируйте в свой проект, не правьте; обновления — из `C:\gpu-registry`.

### Приоритеты — меньше число, выше право

| приоритет | кто |
|---|---|
| 1–9 | владелец из интерфейса: «освободите карту» |
| 10 | работа по прямой просьбе владельца прямо сейчас (чат Claude, задача Codex, кнопка на сайте) |
| 20 | владелец за компьютером (заявка `owner-desk`, кнопка «Я за компьютером», сама снимается в 23:00) |
| 30 | плановые задачи со сроком (ежедневные обновления и т. п.) |
| 50 | фон, который догонит сам — самый низкий |

Владелец управляет картой из интерфейса: **«Пауза для всех»** (приоритет 1 — все ждут) и
**«Я за компьютером»** (20 — днём ждут плановые и фоновые прогоны, то, что владелец попросил сам (10),
идёт). Для проекта это обычные заявки: `may_run` ответит `ok: false`, и нужно уступить.
Ночью (после 23:00) долгие прогоны можно всегда; днём тяжёлое — только когда владельца нет дома.

Фон всегда уступает человеку. Равные приоритеты — по очереди: кто раньше подал заявку,
тот и работает; продление место сохраняет, снятая заявка его теряет.

### Обязательно

1. **Перед каждой порцией работы** — `GET /api/gpu/may_run?project=<имя>&priority=<N>`.
   `ok: false` — ждать (в `holder` — кто держит карту и зачем), спрашивать раз в 30 с.
2. **Долгая работа (больше минуты) — под заявкой:** `POST /api/gpu/claims` на 1–2 часа,
   продлевать раз в 30 минут, по окончании `DELETE /api/gpu/claims/<имя>`.
   Во время работы спрашивать `may_run` не реже раза в минуту; карту забрали — остановиться
   в пределах минуты.
3. **Уступая — выгрузить свою модель:** `POST <ollama>/api/generate {"model": "<модель>", "keep_alive": 0}`.
   Не выгружать, если модель есть в `models` заявки того, кому уступаешь.
4. **Чужие и общие модели не выгружать никогда.** Имя модели владельца не называет:
   `qwen3.5:9b-q4_K_M` грузят и re-analyzer, и evo-archive. Выгружать можно только модель,
   которую в `/api/gpu/projects` указал **только** твой проект.
5. **Держать свой список моделей актуальным:** `PUT /api/gpu/projects/<имя>`
   `{"models": [...], "priority": N, "description": "...", "host": "..."}`.
6. **Помнить про 16 ГБ.** Когда видеопамять заполнена (>~15 ГБ), Windows выгружает её
   в ОЗУ и тормозит весь рабочий стол владельца. Держать запас ~1,5 ГБ (контекст `num_ctx`
   тоже занимает память). Две модели по 7–10 ГБ вместе не помещаются — поэтому и очередь.

### Если реестр не отвечает

Работать по старой осторожной схеме: ничего не выгружать; если на карте (`GET <ollama>/api/ps`)
есть модель не из твоего списка — ждать и проверять раз в минуту. `gpu_client.py` делает
это сам (`fallback_ok`). Ollama недоступна (ПК выключен или владелец ещё не вошёл —
Ollama стартует только после входа) — ждать, не падать.

### Как узнать своё место в очереди

- `GET /api/gpu/may_run?project=<имя>` — `ok`, `holder` (кто держит), `blockers` (все, кто впереди).
- `GET /api/gpu` — сводка: что на карте и чьё, действующие заявки по порядку, проекты.
- `GET /api/gpu/claims` — действующие заявки, первая в списке и держит карту.

### Пример (Python, gpu_client.py)

```python
from gpu_client import GpuClient

gpu = GpuClient("my-project", models=["gemma4:12b-it-q4_K_M"])

# разовый запрос меньше минуты — без заявки, но спросить
gpu.wait_turn(priority=30)
answer = call_ollama(...)

# долгая работа — под заявкой (подаётся, продлевается раз в 30 мин, снимается сама)
with gpu.lease(priority=50, note="ночной перевод", vram_gb=11) as lease:
    for item in queue:
        lease.checkpoint()        # раз в минуту спрашивает реестр; забрали — выгрузит своё и ждёт
        process(item)
```

Без Python — те же вызовы через HTTP:

```bash
curl -s "http://192.168.50.20:11435/api/gpu/may_run?project=my-project&priority=30"
curl -s -X POST http://192.168.50.20:11435/api/gpu/claims -H "content-type: application/json" \
  -d '{"project":"my-project","hours":1.5,"priority":30,"note":"что делаю","models":["..."]}'
curl -s -X DELETE http://192.168.50.20:11435/api/gpu/claims/my-project
```

Имя проекта: латиница в нижнем регистре, цифры, `-`, `_`, до 40 знаков. Новый проект сначала
записывает себя через `PUT /api/gpu/projects/<имя>` (или просит владельца добавить в интерфейсе).
API, поля заявки и правило очереди меняет только реестр на ПК (`C:\gpu-registry`) по согласованию
с re-analyzer — у него копия правила очереди.

## Время

Внутри UTC, наружу Киев (`tz.py` подменяет кодировщик дат FastAPI). Читая
базу через sqlite3 напрямую — это UTC.

## Как принято писать

Комментарий объясняет ПОЧЕМУ, с цифрами. Коммиты по-русски: что было
сломано, чем подтверждается, что сделано. Правки проверять на данных
(«было → стало»), тесты — `pytest tests -q`. Python-синтаксис 3.9-совместимый.
Интерфейс — по-украински, документация и комментарии — по-русски.
