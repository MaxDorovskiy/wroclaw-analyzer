# Wrocław Analyzer — как работать с этим проектом

Младший брат киевского RE Analyzer (репозиторий flatfy-analyzer). Общего кода
нет — общие только решения, которые там окупились. Свой репозиторий:
https://github.com/MaxDorovskiy/wroclaw-analyzer (перенесён из папки
`wroclaw-analyzer/` flatfy-analyzer 18.09.2026 с историей). Подробности: `README.md`,
`docs/ARCHITECTURE.md`, `docs/API.md`, `DEFERRED.md`.

## Правила, которые дороже всего нарушать

0. **Сервер закрыт паролем** (`WRO_WEB_PASS`, логин `admin`; дополнительные
   логины `WRO_WEB_USERS="yulia:..."` с ролью «просмотр»). На Windows всё в
   `deploy/windows/env.ps1`, оттуда же читают триггеры и `safe_restart` —
   менять в одном месте. Пустой пароль = открыт всем (превью на копии).
   Действия каждого логина пишутся в `access_log` (раздел «Журнал»).
1. **Перед перезапуском — не идёт ли прогон.** Только
   `deploy/windows/safe_restart.ps1` (проверка условием, `-Wait` ждёт окна).
   Прогон продажи ≈ 1 час (выдача Otodom+OLX по 15 запросов/мин и хвост с
   карточками), аренды ≈ 30 мин; окна 11:00 / 17:00 / 02:30 Киев + 0-20 мин.
   Пауза — «Прогони → Пауза» или `POST /api/scrape/pause {"hours":N}`
   (0 = до отмены); сворачивает прогон за полминуты, статус `stopped`.
2. **Правки проверять на КОПИИ базы** (`WRO_DB=<копия>`, порт 8021).
3. **Анти-бан:** ≤15 запросов/мин на источник, источники по очереди, никогда
   параллельно с киевскими прогонами, если на том же IP. Otodom за DataDome:
   403 + `x-datadome` — это блок, а не сбой; лечится паузой, `fetch_mode=browser`
   (Chromium), дальше — прокси. Аренда уступает продаже (409 → повтор через 15 мин).
4. **На больших выборках не перебирать ORM-объекты** с `description_pl`/`raw_json`:
   `SCORE_COLUMNS`, `select(...)` нужных колонок, `bulk_update_mappings`.
5. **Ошибка записи в цикле прогона → `db.rollback()`**, иначе сессия отравлена.
   Отметка жизни — `scraper.beat_apart` (отдельная сессия), не commit на
   сессии с открытым курсором.
6. **Новая настройка не сохранится, пока ключ не в `SAFE_KEYS`** (config.py).
7. **Ручные правки владельца скрап не перетирает**: `condition_override`,
   `osiedle_override`, `note`, `is_favorite`, `dedup_detached` (`PROTECTED`).

## Источники — подтверждено на живых ответах 18.09.2026

Адаптеры писались без доступа к площадкам; первый запуск на ПК владельца их
сверил (подробно — `docs/RESEARCH.md` §2.3). Что важно помнить:

- **OLX режет Python-клиент по отпечатку** (CloudFront WAF, 403 «Request
  blocked» на любой адрес, даже robots.txt), а Chromium с того же ПК проходит.
  `fetcher` узнаёт такой блок, сразу зовёт браузер и до конца прогона ходит на
  этот хост только им (JSON — `fetch()` со страницы того же origin). Нужен
  Chromium: `playwright install chromium`. robots.txt OLX разрешает
  `/api/v1/offers/` и `/api/v1/friendly-links/`.
- OLX: настоящее число объявлений — `metadata.visible_total_count`
  (`total_elements` срезан на 1000); сдвиг страницы — из `links.next`; ~12
  рекламных на странице повторяются; friendly-links — путь через запятую;
  телефон API не отдаёт (только признак).
- **Otodom сворачивает квартиры застройщика в `relatedAds` записи-инвестиции**
  — без разворота (`flatten_items`) терялось 40% объявлений. Сами инвестиции
  (`estate=INVESTMENT`) и пригороды, помеченные городом (reverseGeocoding:
  county «wrocławski»), не берём; сколько не взято — в сообщении прогона.
- Otodom: этаж в выдаче — слово (`GROUND`, `THIRD`, `ABOVE_TENTH`); время в
  выдаче — польское местное даже с «Z» (карточка — честный UTC);
  `rentPrice.value=0` = «не заполнено». DataDome на httpx не сработал ни разу
  (≈1500 запросов за день при 14/мин).

Порядок при расхождении полей: `scripts/probe_sources.py` (sale и rent) →
сырые ответы в `%WRO_DATA%/probe` → правка `backend/app/sources/*.py` →
`scripts/make_fixtures.py` (обезличенные фикстуры из тех же ответов) →
`pytest tests -q` → `scripts/reparse.py` на КОПИИ базы, потом на боевой
(переразбирает `raw_json` без скрапа и снимает то, что адаптер больше не
берёт). OLX: id категорий/города меняются — при нуле объявлений проверять их
первыми (`olx_category_*`, `olx_city_id`).

## Перевод

Провайдер — настройка `translate_provider` (ollama по умолчанию — та же
карта, что считает ремонт в Киеве; anthropic / google / deepl по ключу).
Кэш по SHA-1 текста (`translations`). Подсказка и словарь терминов —
`translate.py`, меняли — поднять `PROMPT_VERSION`. Структурные значения —
словарём `i18n.py`; незнакомые копятся в `unknown_values` («Прогони»).
Оригинал хранится всегда. Карту делит другой клиент Ollama: если модель та же,
`translate_ollama_num_ctx` должен совпадать с его CONTEXT в `ollama ps` —
иначе модель перезагружается на каждый запрос (15–25 с против 0).

## География

`geo.py`: 5 дзельниц, 48 осиедле, транскрипция. Сверено 18.09.2026: список —
с geoportal.wroclaw.pl/poi/rejon/7; привязка к бывшим дзельницам (геопортал
её не даёт — дзельницы упразднены в 1991 г.) — с таблицей «Dawna dzielnica»
pl.wikipedia и с самим Otodom (9411 объявлений, расхождений 0). Otodom даёт
под-район (70 имён, все в `ALIASES`), OLX — только дзельницу, и осиедле из
одиночной дзельницы не выводится. Имя дзельницы дважды в цепочке — одноимённый
под-район (`SAME_NAME_PART`).

## Время

Внутри UTC, наружу Киев (`tz.py` подменяет кодировщик дат FastAPI). Читая
базу через sqlite3 напрямую — это UTC.

## Как принято писать

Комментарий объясняет ПОЧЕМУ, с цифрами. Коммиты по-русски: что было
сломано, чем подтверждается, что сделано. Правки проверять на данных
(«было → стало»), тесты — `pytest tests -q`. Python-синтаксис 3.9-совместимый.
Интерфейс — по-украински, документация и комментарии — по-русски.
