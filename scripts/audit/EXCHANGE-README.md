# Обменная папка: Wrocław Analyzer ↔ внешние аудиторы

Общая папка владельца для переписки ассистента проекта (Claude Code на ПК
владельца, Windows) и аудиторов: Codex на том же ПК и любой другой LLM,
которой владелец поручит проверку. Владелец просит одну сторону проверить
другую словами в своём чате — файлы вручную никто не переносит.

Этот файл пишет скрипт выгрузки (`scripts/audit/export_exchange.py`, шаблон —
`scripts/audit/EXCHANGE-README.md`) и перезаписывает при каждой выгрузке.

## С чего начать аудитору

1. `STATE.json` — какой коммит выгружен, от какой базы патчи, прошла ли вычистка.
2. `snapshot/code/docs/audit/EXTERNAL-AUDIT.md` — план аудита, порядок чтения,
   формат отчёта, задания для LLM и для Codex (QA).
3. `chats/00-оглавление.md` → `chats/02-сводки-сжатия.md` → `chats/01-реплики-владельца.md`.

## Кто что пишет

| папка | пишет | что там |
|---|---|---|
| `snapshot/code/` | Claude (скрипт) | код на текущем коммите (git archive, без истории). Перезаписывается при каждой выгрузке |
| `snapshot/docs/` | Claude (скрипт) | CLAUDE.md, DEFERRED.md, README.md проекта; `owner-rules-all-projects.md` — правила владельца для всех проектов; `claude-memory/` — память Claude по проекту между сессиями |
| `snapshot/evidence/` | Claude (скрипт) | `data-metrics.md` — метрики с боевой базы (только чтение), `tests.txt` — прогон тестов, `health.json` — ответ боевого сервера |
| `changes/<база>..<HEAD>/` | Claude (скрипт) | патчи коммитов с последней проверки аудитора и `00-список.md`; сообщения коммитов — журнал решений: что было сломано, чем подтверждено, что сделано |
| `from-claude/` | Claude | `REPORT-<дата>[-<тема>].md` — отчёт в конце каждого ответа владельцу; `ANSWER-<дата>-<ЧЧММ>.md` — полный текст ответа владельцу; `RESPONSE-<дата>.md` — вердикт по каждой находке аудитора; `attachments/<дата>/` — реплики и вложения владельца дословно |
| `chats/` | Claude (скрипт `export_conversations.py`) | ОЧИЩЕННАЯ переписка: оглавление, сводки при сжатии контекста, все реплики владельца, сессии целиком (`sessions/`), субагенты (`sessions/subagents/`) |
| `from-codex/` | Codex | `AUDIT-REPORT-<дата>.md`, `QA-REPORT-<дата>.md`, `REVIEW-<дата>-<тема>.md`; `REVIEWED_HEAD` — одна строка, последний проверенный коммит |
| `from-<имя>/` | другая LLM (или владелец за неё) | то же, что from-codex: например, `from-gemini/AUDIT-REPORT-<дата>.md`. Чат-LLM без доступа к файлам отдаёт отчёт текстом — владелец сохраняет его сюда как есть |
| `STATE.json` | скрипт | что выгружено, от какой базы, итог проверки на секреты и применимость патчей |

Чужие файлы не правят: ответ — новым файлом в своей папке.

## Как проходит круг

1. Владелец аудитору: «проверь проект» (первый раз — задание из
   `EXTERNAL-AUDIT.md`) или «проверь последние изменения Claude». Аудитор
   читает `STATE.json`, `changes/…/00-список.md`, патчи, `from-claude/`
   (последние REPORT/RESPONSE), при нужде — `snapshot/` и `chats/`. Пишет отчёт
   в свою папку в формате находок F-… и запросов Q-… и обновляет `REVIEWED_HEAD`.
2. Владелец Claude'у: «аудитор ответил». Claude проверяет каждую находку на
   живых данных (только чтение, правки — на копии базы), чинит подтверждённое,
   отвергнутое объясняет с числами, выполняет запросы Q-…, отвечает
   `from-claude/RESPONSE-<дата>.md` и обновляет выгрузку.

## Чего здесь не бывает никогда

База, фотографии, сессии кабинетов, пароли, номера телефонов, адреса почты.
Выгрузка сама проверяет результат шаблонами вычистки и падает, если что-то
осталось. Запросы к живой базе — через Q-… в отчёте: их выполняет Claude и
кладёт результат в свой ответ. Codex на ПК может читать ночную резервную
копию базы (`C:\wro-data\backup\`, только копию в своей временной папке, не
боевую `wro.db`) — с тем же запретом выносить в отчёт телефоны и имена.
